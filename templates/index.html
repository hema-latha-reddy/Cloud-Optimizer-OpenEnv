📖 User Guide & How It Works

🎯 What is Cloud Optimizer Pro?

Cloud Optimizer Pro is an AI training environment that simulates real-world cloud infrastructure management. Your goal is to maintain optimal system performance by adjusting the number of active servers based on incoming traffic.

🏗️ How It Works

  • Traffic - Simulated user requests coming to your servers (100-500 req/s)
  • Servers - Computing resources you can scale (1-10 servers)
  • Latency - Response time in milliseconds (Target: 150-250ms)
  • Reward - Performance score (0.0 to 1.0)

🎮 Three Difficulty Levels

  • 🟢 Easy - Stable traffic (100-200 req/s). Perfect for beginners.
  • 🟡 Medium - Oscillating traffic (120-280 req/s). Tests your adaptability.
  • 🔴 Hard - Stress test with random spikes (100-500 req/s). Ultimate challenge!

🚀 Getting Started

  1. Select a Task - Click on Easy, Medium, or Hard button to choose difficulty
  2. Observe Metrics - Watch Traffic, Servers, Latency, and Reward
  3. Take Action - Click one of three action buttons:
    • 🔻 Scale Down - Remove a server (when latency is too low)
    • ⚖️ Maintain - Keep current server count (when latency is optimal)
    • 🔺 Scale Up - Add a server (when latency is too high)
  4. Monitor Charts - Watch real-time latency and reward history
  5. Reset Anytime - Click Reset to start fresh

💡 Pro Tips

  • ✅ Target Zone: Keep latency between 150-250ms for maximum reward (1.0)
  • 📊 Watch the Charts: They show your performance trend over time
  • 🔄 Multiple Episodes: Reset and try different strategies to improve your score
  • 📝 Activity Log: Track every action you take and its effect

📊 Understanding the Metrics

🟢 Traffic Load

Number of requests per second hitting your servers. Higher traffic = need more servers.

🖥️ Active Servers

Current number of servers running. Each server can handle ~25-30 req/s optimally.

⏱️ Latency (ms)

The most important metric! How long users wait for a response.

  • 🟢 150-250ms → Perfect (Reward: 1.0)
  • 🟡 100-150ms or 250-300ms → Good (Reward: 0.5-0.9)
  • 🔴 <100ms or >300ms → Poor (Reward: 0.0-0.4)
💰 Reward

Your performance score. Higher is better! The goal is to keep reward close to 1.0.

📈 Understanding the Charts

  • Latency History - Shows how latency changes over time. You want this in the green zone (150-250ms).
  • Reward History - Shows your performance trend. Should go up as you optimize!

📝 Reading the Activity Log

The log shows every action you take with timestamps. Use it to understand what worked and what didn't.

⭐ Basic Rule

Latency too HIGH (>250ms) → Click Scale Up (add servers)
Latency too LOW (<150ms) → Click Scale Down (remove servers)
Latency OPTIMAL (150-250ms) → Click Maintain (stay steady)

🏆 Task-Specific Strategies

🟢 Easy Task (Stable Traffic)
  • Find the right server count once, then mostly maintain
  • For traffic ~150 req/s, aim for 5-6 servers
  • You can easily achieve 0.95+ average reward
🟡 Medium Task (Oscillating Traffic)
  • Expect traffic to go up and down - don't over-react!
  • Use wider thresholds (react only when latency >280ms or <120ms)
  • Sometimes maintaining is better than constantly scaling
🔴 Hard Task (Stress Test)
  • Be aggressive with scaling up when traffic spikes
  • Keep more servers ready (aim for 8-10 servers)
  • Quick action is critical - don't wait too long!
📐 Formula Reference
Latency = (Traffic ÷ Servers) × 8
Optimal Servers ≈ Traffic ÷ 25
Reward = Based on distance from 150-250ms target
